This project implements an **end-to-end Object Detection pipeline** from scratch using a custom-trained model. It allows users to upload images and receive real-time bounding box predictions and classification results.

# Object Detection Data Preparation Pipeline

This pipeline covers the workflow from manual image annotation to the final generation of a YOLO-compatible dataset.

## 0. Image Annotation (Pre-processing)
The images were manually annotated using **LabelImg**. 
- **Format:** Pascal VOC.
- **Output:** For every image, a corresponding `.xml` file was generated containing the bounding box coordinates and class labels.

## 1. Library Imports
Essential libraries are used for file system management, data manipulation, and XML parsing:
- `os`, `shutil`, `glob`: File and directory handling.
- `pandas`: Data structuring and cleaning.
- `xml.etree.ElementTree`: XML parsing.

## 2. File Discovery
The script locates all `.xml` files generated by LabelImg in the `./data_images/` directory and normalizes file paths for cross-platform compatibility.

## 3. XML Data Extraction
A function `extract_text` parses the LabelImg output:
- **Metadata:** Captures image dimensions (width/height).
- **Object Info:** Extracts the class `name` and bounding box corners (`xmin`, `xmax`, `ymin`, `ymax`) for every object in an image.

## 4. YOLO Coordinate Transformation
Because YOLO requires coordinates relative to the image size (0 to 1), the absolute pixels from LabelImg are transformed:
- **Center X/Y:** Calculated as the midpoint of the box divided by the image dimension.
- **Width/Height:** Calculated as the span of the box divided by the image dimension.

## 5. Dataset Splitting
To prepare for model training:
- Unique images are identified to prevent overlapping.
- The data is split into **80% Training** and **20% Testing** sets.

## 6. Label Encoding
Categorical labels (e.g., 'dog', 'car') are mapped to integer IDs (e.g., 0, 1) using a label dictionary, as required by mathematical models.

## 7. Final Dataset Organization
The script automates the final folder structure:
- **Directories:** Creates `train/` and `test/` folders.
- **Image Migration:** Moves `.jpg` files into their respective folders.
- **Label Generation:** Creates a `.txt` file for each image containing the Class ID and the four normalized YOLO coordinates.

# YOLOv5 Deployment and Web Application

This section describes the implementation of the inference engine and the web-based interfaces used to interact with the object detection model.

## 1. Inference Engine (`YOLO_Pred` Class)
To ensure the model is portable and efficient, the trained YOLOv5 model is loaded in **ONNX format** using OpenCV’s DNN module.
- **Initialization:** Loads the `.onnx` weights and the `data.yaml` file (which contains class names like person, car, etc.).
- **Image Preprocessing:**
    - Converts input images into a square format (adding black padding if necessary).
    - Resizes images to **640x640**.
    - Scales pixel values (0-255) to a normalized range (0-1).
- **Post-processing:**
    - **Filtering:** Uses a confidence threshold to ignore weak detections.
    - **NMS (Non-Maximum Suppression):** Removes redundant, overlapping boxes for the same object.
    - **Visualization:** Draws bounding boxes and percentage labels on the final image.

## 2. Streamlit Web Interface (`Home.py`)
The application is organized into a multi-page Streamlit dashboard.
- **User Navigation:** A centralized landing page that lists the 20 detectable classes (e.g., Bicycle, Boat, Cat, Dog).
- **Configuration:** Page settings are optimized for a 'wide' layout with custom icons for a professional look and feel.

## 3. Static Image Detection (`1_YOLO_for_image.py`)
This module handles one-time detection tasks on uploaded files.
- **File Uploader:** Supports `.jpg`, `.jpeg`, and `.png` formats.
- **Validation:** Checks file types and sizes before processing.
- **Interactive Preview:** Displays the original image alongside the "Predicted Image" once the YOLO model processes the data.

## 4. Real-Time Video Stream (`2_YOLO_webrtc.py`)
For live scenarios, the app utilizes WebRTC (Web Real-Time Communication).
- **Webcam Integration:** Accesses the user's camera feed directly through the browser.
- **Frame Callback:** Every individual frame from the video stream is passed through the `yolo.predictions()` function in real-time.
- **Optimization:** Processes frames in BGR format to remain compatible with OpenCV's drawing functions before displaying them back to the user.

## 5. Model Assets
- **`best.onnx`:** The optimized weights exported after the training phase.
- **`data.yaml`:** Configuration file defining the number of classes (`nc`) and their corresponding string names.
